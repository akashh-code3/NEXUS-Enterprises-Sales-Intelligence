# NEXUS — Enterprise Sales Intelligence & Strategic Analytics Platform

NEXUS is an enterprise-style retail sales intelligence platform with an interactive Streamlit command center, a reusable analytics layer, MySQL star schema, Power BI handoff, data-quality controls and management-ready reporting. It uses a restrained corporate visual system and does not use any third-party corporate logo or proprietary brand assets.

## What is included

- **Dataset generation:** reproducible 105,000+ row transaction dataset with repeat customers, product/category economics, seasonal demand, regional footprints, order status and a small set of intentionally introduced quality defects.
- **Data quality pipeline:** type and category standardization, exact-duplicate removal, missing-value handling, IQR outlier profiling, sales-rule validation, calculated fields, CSV/XLSX exports and a JSON quality report.
- **MySQL:** date, customer, product and geography dimensions with a transaction fact table and relational constraints. The SQL analysis library contains 30 MySQL 8 queries.
- **Command center:** filter-aware Streamlit workspace with light/dark themes, executive KPIs, revenue trajectory, category and regional profitability, order mix, product leaders and seasonality.
- **Customer intelligence:** transparent recency/frequency/monetary scores, actionable customer segments, cohort acquisition and retention matrix, repeat behavior and a discount–margin rank-association statistic.
- **Forecast & planning:** scikit-learn seasonal trend baseline, held-out recent-period MAE, SciPy residual-based planning interval and explicit limitations.
- **Data assurance and reports:** quality-control register, filtered CSV, multi-sheet Excel management pack and a concise PDF business brief.
- **Optional MySQL-backed dashboard:** set `SALES_DATABASE_URL` and choose MySQL as the dashboard source. CSV remains available as the no-configuration default.
- **Power BI handoff:** star-schema model, starter DAX measures, cleaned CSV and Excel extracts. A `.pbix` file is not generated by this Python project.
- **`index.html`:** static visual preview; the filterable analytics workspace is `app.py`.

## Quick start

Use Python 3.10+ and install the dependencies:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python scripts/generate_data.py
python scripts/clean_data.py
streamlit run app.py
```

Default outputs:

- `data/raw/sales_raw.csv`
- `data/processed/sales_cleaned.csv`
- `data/processed/sales_cleaned.xlsx`
- `data/processed/quality_report.json`

In the left navigation, choose **Executive Command Center**, **Customer Intelligence**, **Forecast & Planning**, or **Data & Reporting**. The date, region, category and order-status controls apply consistently across views and generated reporting.

Run the focused analytics and export tests:

```powershell
python -m unittest discover -s tests -v
```

The generator accepts `--rows`, `--seed` and `--output`. It rejects counts below 100,000.

## MySQL setup and loading

Install and start MySQL 8. Create the database and tables from the project root:

```powershell
mysql -u root -p < sql/schema.sql
$env:SALES_DATABASE_URL = "mysql+mysqlconnector://USER:PASSWORD@localhost:3306/enterprise_sales"
python scripts/load_mysql.py
```

The loader uses idempotent upserts for dimension and fact records. Do not put database credentials in source control; use a local environment variable or an approved secret manager.

The app's optional MySQL source reads the normalized schema and returns the dashboard's row-level columns. It requires the schema and loader to have been run first. The connection is not attempted unless `SALES_DATABASE_URL` is set.

Run the analyses in `sql/analysis.sql` using a MySQL 8 client or your preferred SQL IDE.

## Power BI

Connect Power BI Desktop to the MySQL `enterprise_sales` schema or import `data/processed/sales_cleaned.csv` for a lightweight prototype. Relate each dimension's key to its corresponding fact foreign key (one-to-many, single direction). Use `powerbi/measures.dax` as starter measures. For a production model, set `dim_date[full_date]` as the date table and apply an incremental-refresh policy to the fact table.

## Data notes and metric definitions

- Distinct base records are at least 100,000; the raw file is slightly larger because it contains intentional exact duplicates for the cleaning exercise.
- Revenue is quantity × unit price × (1 − discount). Cancelled/returned transactions are zero realized revenue; their cost remains and is recognized as negative profit.
- The cleaning stage reports IQR outliers rather than automatically dropping them. High-value transactions can be genuine and should be investigated before exclusion.
- Revenue, profit and margin in the dashboard exclude cancelled/returned orders by default. Toggle them into view for operational status analysis.
- RFM values and customer cohorts reflect the active filters; narrowing the date range also narrows the observed customer history. Cohort retention is descriptive and should be interpreted with cohort maturity in mind.
- The revenue forecast uses a seasonal-trend baseline. Its holdout MAE and residual interval are planning diagnostics, not guarantees; the method does not model promotions, inventory limits, pricing changes or external events.
- Discount/margin association is observational, not causal evidence.
- Synthetic data is for demonstration and does not represent actual customers or company performance.
